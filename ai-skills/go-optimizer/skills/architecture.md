# 子 Skill：架构与可维护性分析（工单 09）

## 用途
评估模块职责与边界合理性，提示长期演进风险点。

## 适用场景
- 包职责混杂、循环依赖、包体过大
- 接口定义过宽/过窄、实现与抽象耦合
- 业务逻辑堆积在 handler、缺乏分层
- 配置硬编码、缺乏可配置化

## 分析要点
1. 包边界：是否存在循环依赖、god package。
2. 分层：handler/service/repository 职责是否清晰。
3. 接口：是否面向接口编程、依赖是否可注入。
4. 可配置化：业务规则与常量是否硬编码。

## 输出要求
遵循统一输出结构；架构类结论通常判为中风险（长期影响），需说明演进背景与依据文件。
