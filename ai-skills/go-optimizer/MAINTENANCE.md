# 维护说明（工单 09）

## 扩展方式
- **新增维度**：在 `skills/` 下新增一个 Markdown，按“用途 / 适用场景 / 分析要点 / 输出要求”四段编写，并在 `SKILL.md` 维度表登记。
- **升级维度**：直接修改对应子 Skill 文件，保持统一输出结构不变。
- **下线维度**：从 `SKILL.md` 维度表移除，子文件可保留归档。

## 不破坏复用性的约束
- 统一输出结构（output-template.md）不得随意删字段；新增字段需向后兼容。
- 子 Skill 必须保持“基于上下文、可解释、分级、可执行”四原则。
- 触发方式（.cursor/rules 与 .trae/rules）与 IDE 解耦，更换 IDE 仅需新增对应规则文件。

## 团队资产化
- 优化结论可追加到项目“优化记录”文档，作为 PR/MR 审查与工程质量评估依据。
- 建议将该目录纳入版本管理，随项目迭代共同维护。
