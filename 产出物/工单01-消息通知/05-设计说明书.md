# 工单01 消息通知与告警中心 — 设计说明书

> **工单编号：01｜消息通知**　需求来源：智能快寄柜 10 份任务工单 V1.x　创建人：邹世军　出品：八维文化与产业研究院（内容由 AI 生成，仅供参考）

## 1. 需求概述
构建统一通知告警中心，支持站内信/短信/邮件/回调多渠道，模板+变量渲染，去重频控，失败重试升级，审计与监控看板，覆盖 8 类业务场景。工时：3 人日。

## 2. 设计目标与约束
- 投递分位时延达标（P95≤300ms）、失败率可控、模板变量安全转义。
- 全局铁律：`@ticket` 编号注释、单测≥70%、统一错误码与日志、接口压测报告、事务/幂等/鉴权/脱敏/审计、可配置化、引用真实来源。

## 3. 总体架构
```
业务事件 → 场景路由(SceneNotify) → 模板渲染(Dispatch) → 去重频控 → 渠道投递
                                                    ↓
                                          落库 notify_message → 监控/审计
```
- **Handler 层**（`internal/handler/notify.go`）：Send / SendScene / Scenes / Records / Monitor。
- **Service 层**（`internal/service/notify.go`）：Dispatch、SceneNotify、NotifyRecord、NotifyMonitor、renderTemplate、checkDedupe 等。
- **Model 层**：`notify_template`、`notify_message`。

## 4. 核心流程
1. **场景触发**：业务传入 scene + 接收方 + 变量，SceneNotify 路由到 1..N 个模板。
2. **模板渲染**：renderTemplate 解析 `{var}` 并做 HTML/内容安全转义，防止注入。
3. **去重频控**：checkDedupe 依据 dedupe_key + 时间窗判断是否重复/超频。
4. **投递与重试**：调用渠道适配器投递，失败写入 status=2/3 并按退避重试，超限升级。
5. **审计与回执**：全过程写日志与审计报表，监控看板聚合指标。
